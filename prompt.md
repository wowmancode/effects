Data model: Project has a list of Clip objects (sequential, ordered, hard cuts between them — no transitions). Each Clip has: id, sourceUri, trimStartMs, trimEndMs, a TransformSettings (scale/rotation/offset, whole-clip, not time-ranged), and its own effectSegments and audioSegments lists (TimelineSegment: id, effectId, startMs/endMs relative to that clip, enabled, params map). Project itself just holds clips: List<Clip> plus overall metadata (name, createdAt). Serialize to/from JSON via kotlinx.serialization for save/load and shareable presets.
Effect registry: every effect (visual or audio) implements a common LecEffect interface (id, displayName, category [EFFECTS/TRANSFORM/AUDIO], params list, toMediaEffect()). New effects = new class + register in EffectRegistry — this is the only wiring point; timeline UI, param panel, save/load, and export must all work generically off this registration. This extensibility is the most important design requirement, since effects get added gradually over time.
MVP effects — Visual: echo/ghost-trail, hue rotate, color invert, zoom (static+oscillating), chromatic aberration, VHS/scanline overlay, freeze frame, mirror/flip. Transform: scale, rotation, position offset. Audio: echo, chorus, pitch/speed change.
UI — 4 screens:
Import: pick one or more videos (SAF), shown as a reorderable list before entering the editor; also add a "+" to append another clip later from the Editor screen itself. Each shows filename/duration/thumbnail.
Editor (core screen): a real, live ExoPlayer preview at top with effects applied — not a placeholder label. Below it, a horizontal, scrollable timeline: a video reference strip showing actual clip blocks sized proportionally by duration with a visible boundary between clips (hard cut, no gap); an Effects lane below it showing segment blocks positioned/sized by their actual startMs/endMs (not a list — segments can visually overlap when their time ranges overlap); an Audio lane below that, same pattern. Include a playhead indicator synced to preview position. Segment blocks support drag-to-resize on their edges. Tapping empty lane space within a clip's region adds a new segment there (opens the effect picker); tapping an existing block selects it and opens its param panel; tapping a clip on the video strip selects that clip and opens its Transform panel. Bottom edit panel has 3 buttons: Effects / Transform / Audio — auto-switches to match what's selected; shows an empty/prompt state when nothing is selected, not a running list of every effect ever added.
Param panel: one generic layout (sliders/inputs) driven entirely by the selected effect's declared params — no per-effect hand-written UI.
Export: progress bar during Transformer export (concatenating clips with hard cuts, applying each clip's transform/effects/audio), then done state with share/save.
